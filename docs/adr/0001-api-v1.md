# ADR 0001 — API V1 : paiement, stockage, borne

- Statut : accepté
- Date : 2026-11-05
- Auteur : dev-backend

## Contexte
V1 doit permettre de « payer depuis l'app » sans contrat eMSP signé, sur iOS, Android (Expo Go) et web, sans clé payante, hébergée gratuitement (Render free, une instance qui s'endort).

## Décisions

### 1. Stripe Checkout (page hébergée) plutôt que PaymentSheet
- Checkout s'ouvre dans un navigateur (`expo-web-browser` / onglet web) : **fonctionne dans Expo Go et sur le web sans module natif** ; PaymentSheet exige `@stripe/stripe-react-native` (build de développement) et ne couvre pas le web.
- Pré-autorisation : `mode=payment`, `payment_intent_data.capture_method=manual`, montant `PREAUTH_CENTS`, capture `amount_to_capture = totalCents` à l'arrêt, annulation du PaymentIntent si `totalCents = 0`.
- PCI : aucune donnée de carte ne transite par l'API (SAQ A) ; seul l'id `pi_…` est conservé.
- Coût : une redirection en plus et une UX moins intégrée. Réévaluer PaymentSheet quand l'app passera en build natif.

### 2. Store en mémoire
- Une seule instance gratuite, sessions courtes : `Map` en mémoire derrière l'interface `SessionStore`, purge à 24 h, taille bornée.
- Conséquence assumée : un redémarrage (déploiement, mise en veille Render) perd les sessions en cours. Acceptable en démo ; **bloquant pour du paiement réel** → store persistant (Postgres/Redis) avant tout passage en live.

### 3. Borne simulée (`SimulatorCharger`)
- Rampe linéaire sur 20 s jusqu'à `SIM_POWER_KW`, énergie intégrée × `SIM_SPEED`, calcul paresseux à la lecture (aucun timer, compatible mise en veille).
- Derrière l'interface `ChargerAdapter { start, stop, read }` : un adaptateur eMSP marque blanche / OCPI s'y substituera.
- `start` reçoit `maxEnergyWh` (dérivé de la pré-autorisation) : la borne plafonne d'elle-même, l'API arrête la session dès `costCents + feeCents ≥ preauthCents`.

## Précisions et écarts au contrat
- `returnUrl` refusée (400 `invalid_return_url`) si elle ne commence pas par un `ALLOWED_RETURN_PREFIXES` ; frontière d'hôte contrôlée (`http://localhost.evil.com` refusé), pas d'identifiants dans l'URL.
- Ajout : `POST /mock-checkout/:id/cancel` (lien « Annuler » de la page démo, en formulaire POST pour ne pas annuler sur un simple préchargement de lien) et `GET /checkout-return/:id` (relais Stripe : Checkout n'accepte que des URL http(s), les schémas `branche://` / `exp://` y sont redirigés). La `returnUrl` n'est pas exposée dans `Session`.
- `/mock-checkout/*` n'existe qu'en mode `mock` (sinon un client démarrerait une charge sans payer).
- Clé `sk_live_` refusée en V1 : la borne étant simulée, aucun débit réel ne doit être possible.
- `totalCents` vaut `feeCents` dès le démarrage (0 kWh) — conforme à la formule `min(cost + fee, preauth)`.
- Erreurs : `{ error: { code, message } }` en français ; 409 `invalid_state` pour une transition impossible (stop avant paiement, annulation après démarrage).
- Session non payée sous 30 min : `cancelled` avec `error.code = checkout_expired`.
